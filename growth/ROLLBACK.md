# Roll back LoopKit Growth

1. In the Cloudflare dashboard open **Workers & Pages → loopkit-growth → Settings → Variables and Secrets**. Set `DISCOVERY_ENABLED=false`, set `PUBLIC_API_DAILY_LIMIT=0` if public tool endpoints also need to pause, and deploy the settings. Delete the growth Cron trigger under **Triggers → Cron Triggers** to pause scheduled housekeeping as well. Wait up to one minute for an in-flight scan lease. Do this before deploying an older Worker version if the problem involves discovery.
2. For a code regression, select **Deployments** on the growth Worker and roll back to the previous known-good version. Verify its environment variables, secrets, custom domain and Cron configuration separately. Restore the intended Cron and discovery settings after validation. If decommissioning the entire service, remove **only** the growth Worker's custom domain and revoke the deployment token, agent keys and analytics bridge key. Keep Access protection enabled until the admin hostname has been removed.
3. Export or snapshot the growth D1 database before restoring data. Use its Cloudflare dashboard backup/Time Travel facilities for the account's available retention. The initial migration can stay in place when reverting code. Never point the deploy workflow at the main site's database or delete the database to roll back a Worker version. If the service is paused, D1 housekeeping also pauses when its Cron is removed. Delete retained growth records under your approved retention process before resuming or disposing of the database.
4. To disable the website analytics integration, set `GROWTH_ATTRIBUTION_ENABLED=false` on the main site Worker. Its existing event ingestion falls back to the original procedure. Revoke the two `GROWTH_ANALYTICS_KEY` copies when the aggregate bridge is no longer needed. To remove widget controls, roll back the main site to its own prior verified deployment or revert the website patch on the authoritative live branch. The Supabase migration adds nullable analytics columns and service-only functions. Leave those in place through the rollback window and let established analytics retention purge the data.
5. Confirm the homepage, catalog and existing project links still load. If the growth Worker remains reachable, confirm signed-out admin and credentialless Meta Muse requests remain blocked. Verify the intended D1 database and Cron details on the growth Worker.
